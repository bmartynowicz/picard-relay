# Development and maintenance

The release-only `scripts/install-ci-cosign.mjs` installs fixed Cosign v3.1.4
through the official GitHub asset API. It retains the v3.1.3 bootstrap digest and
both keyless-identity and KMS checks from
[the pinned installer](https://github.com/sigstore/cosign-installer/blob/b9c35392b7c1401bcc77d30c9b07cf4b1c7a7b07/action.yml),
and adds exact published asset digests from the
[official release](https://github.com/sigstore/cosign/releases/tag/v3.1.4).
It fails before installation on any missing asset, digest mismatch or signature
failure. Offline tests run normally and jitless in the signing job. This does
not change release-signature identity, host policy, runtime modules or providers;
the installer is never shipped to relay hosts.

## Source map

| Path | Role |
| --- | --- |
| `src/`, `test/` | Reusable offline/preview relay core and shared tests. Root `npm start` uses this tree. |
| `experimental/runtime-control/src/` | Complete signed-runtime source snapshot. This is the source packaged for enrolled hosts. |
| `experimental/runtime-control/src/oracle-service.mjs` | Listener, configuration, owner authentication, typed status and embedded base console. |
| `experimental/runtime-control/src/admission-ui.mjs` | Optional Requests UI, result recovery/formatting and the narrowly bound reviewed-correction note. |
| `experimental/runtime-control/src/admission-*.mjs` | Catalogue, approval, policy, durable admission and dispatch boundaries. |
| `experimental/runtime-control/src/relay-store.mjs`, `dispatcher.mjs`, `receiver.mjs`, `protocol.mjs` | Durable lifecycle, claims/invocation boundary and signed transport. |
| `experimental/updater/` | Signature/source checks, fixed service adapter, host update transaction and read-only activity observer. |
| `scripts/build-release.mjs`, `scripts/package-signed-release.mjs` | Build the bounded manifest/bundle and publication envelope. |
| `.github/workflows/sign-release.yml` | Linux release checks, Sigstore signing and source publication; no host deployment. |
| `tools/`, `examples/` | Explicit operator clients and offline demonstrations; not all are in the runtime artifact. |

Do not copy changes indiscriminately between the two source trees. Determine which runtime the request concerns. Some root tests intentionally import the signed-runtime source. Host support code such as the updater and activity observer is outside the replaceable 20-module runtime bundle.

## Local checks

Use Node.js 24 and OpenSSL. CI pins Node 24.22.1. No npm dependency installation is needed.

```sh
# Offline demo and core/preview checks
npm run demo
npm test

# Exact release-gate commands from the repository root
npm --prefix experimental/updater test
npm --prefix experimental/runtime-control test
npm --prefix experimental/runtime-control run test:socket

# Documentation links and machine-readable metadata
npm run docs:check
```

The complete suites are qualified on Linux. Native Windows can run many pure/UI checks but does not qualify POSIX ownership, directory-FD state access, permissions or Unix sockets. A denied socket test is blocked, not passed. Tests create temporary fixtures and make no live provider call. Use a separate test directory and no production state/configuration.

For a console change, start with the relevant UI tests, then run the release checks. Tests exercise authentication clearing, stale/failure behavior, request single-flight, result recovery, terminal no-retry state, route/filter history and exact original-text preservation. Normal and `--jitless` runs matter because the enrolled runtime uses the native HTTPS path on constrained hosts.

## Editing the embedded console

The base `CONSOLE_HTML` is a JSON string literal in `oracle-service.mjs`. Decode, edit and re-encode it with a script that asserts each intended replacement exists exactly once. Avoid broad replacement of unrelated runtime behavior. `admissionConsoleHtml` composes the optional Requests view and checks its insertion points.

Changing HTML/script requires reviewing the content-security-policy hashes generated by the handler and updating deliberate exact-source pins in `console.test.mjs` / `console-ui.test.mjs`. A new hash is not a substitute for behavioral checks. Keep generated result content inert: use text nodes and a constrained renderer, never `innerHTML` or execution.

The current correction note is tied to entry identity, input hash, result reference and exact original response body. A mismatch must hide it. Adding a generic review editor, changing authority or allowing generated links/HTML would be a separate feature.

## Browser validation

Inspect the actual changed flow at desktop, 390px and 320px widths. For history changes reproduce browser Back/Forward as well as reload; for result changes check both known inputs and original text. Confirm no page overflow, reachable controls, visible focus, proper heading levels and preserved disabled/spent approvals. Use synthetic read-only fixtures before merging, then verify the authorized deployment through authenticated HTTPS.

For status/history changes, test mixed-owner/task records and reconcile the actual authenticated console counts/list with the matching owner/task durable ledger.

Keep local-fixture screenshots, tests, CI, installed release identity and live screenshots clearly distinguished in evidence. A synthetic preview does not prove an authenticated deployment or a successful model call.

## Counter motion preview

Run `node examples/console-motion-preview.mjs`, then open `http://127.0.0.1:4390`.
The fixture binds only to loopback, uses synthetic counts, and creates no provider
adapter, durable database, credential or grant. Its controls change in-memory
samples through the normal console status renderer. Try an increase, carry and
decrease, then Pause motion or your browser's reduced-motion preference. The
carry/decrease controls establish a starting number; Apply sample change makes
the next transition. Stop the fixture with Ctrl+C.

These controls are outside the production console. Their local POST route is
fixture-only and is not part of the signed 20-module runtime or public API.

## Keep the documentation current

For an independent Linux check, the [coding-agent workflow](../experimental/compute-broker/CODING-WORKFLOW.md) prepares one exact public-source request and retrieves a validated Picard receipt through read-only GitHub access. Worker v2 runs the root, updater, signed-runtime, real socket, broker normal/jitless and documentation groups, returning each exit code. Run the same fixed plan locally with `npm run check:repository` on Linux, Node 24, npm and OpenSSL. Existing task authorization applies; preparation never publishes or dispatches by itself. Visual and live-provider acceptance remain separate where required.

Start at [README.md](README.md). Update `project-map.json` if capabilities, paths or hard limits change. `work-register.json` is the structured source for the public work snapshot; keep its human summary in `WORK-REGISTER.md` consistent. Give every bug/feature a stable ID, explicit state and evidence/limitation note. Treat backlog entries as information, not authorization to execute work.

Update [Status](STATUS.md) only with dated evidence and distinguish verified deployment from source-only implementation and human acceptance. Do not commit credentials, live environment files, private ledger/auth state or raw private operational logs. Existing historical review documents should link to current guidance rather than silently changing the meaning of their earlier verification claims.

Use [Operations](OPERATIONS.md) for release, installation and recovery. Preserve dirty/in-use checkouts and unrelated work; use an isolated branch or checkout for changes.

## V1 workspace checks

Use npm run preview:v1 for the disposable browser fixture. It binds loopback only, clearly labels synthetic output and makes no external provider calls. The signed runtime package includes npm run test:workspace for normal/jitless request, HTTP-authentication, real-marker and backup qualification. Native Windows checks are useful while editing; Linux is required for the complete owner-auth, marker and socket boundary.
